## 1a. The copy-paste leg and its baseline (#138, 2026-10-14)

## 1b. The clippy leg's lint table and its exceptions (#132, 2026-10-14)

[M] The configuration, harness/Cargo.toml (the harness is its own one-crate workspace, so the table is the workspace's):

```toml
[workspace]

[workspace.lints.clippy]
unwrap_used = "deny"
expect_used = "deny"
panic = "deny"

[lints]
workspace = true
```

and harness/clippy.toml, `allow-unwrap-in-tests = true`, `allow-expect-in-tests = true`, `allow-panic-in-tests = true`: a `#[test]` function or a `#[cfg(test)]` module may unwrap, its failure being the test's. The leg runs `-D warnings`, so every other clippy lint is denied too.

[M] Where money moves the sites were fixed, not allowed: the node drivers and submitters (harness/src/txroad.rs, rpc.rs, block.rs, engines.rs, txraw.rs; the binaries run_svnode, oracle_chain and run_scenarios with harness/src/scenarios/; run_teranode by the patch below) and the record and report writers (run_bsvrs, run_engine, run_diff by the patch below; stamp.rs and spec_recorded had no site outside tests) return an `Err` through harness/src/fail.rs's `or_err` and exit 1 where an unwrap, expect or panic stood. A run that used to panic stops with exit 1 instead of 101 and the words of the failed call (the former `expect` text, else the call's own text); the usage errors keep exit 2. Two library wrappers still panic for the callers that have not moved, `EngineConfig::from_json` (rules_check) and `block::p2pkh_spend`, and run_diff and run_teranode reach them until their patch records land (§1b's last paragraph). In run_teranode's funding road a malformed node answer stops the run with exit 1 as the panic did, never the run's funding_wall, and a prevout script that is not hex stops it too, never an exclusion the record carries. An `#[allow]` stays on those paths only where the failure is an invariant (a fixed key, a signer, a fixture's own projection) or a deliberate stop its reason names (run_teranode's RPC journal write, the scenarios' date(1) and the pinned node's gettxout value), on the function, with its reason; those sites still stop by a panic, exit 101.

function, field or local (never at a crate root). This includes `rules_check::list_class`, which writes the optional

## 5. The hosted gate (#116, 2026-10-18)

[D] until a pull request on the public repository runs it on GitHub's runners; the dry run on the box, every job's commands in the workflow's order with the pinned clones out of reach as on a runner, is [M] (docs/records/20261018-024333-make-check-hosted.txt: GREEN, the twenty-nine legs' own lines present).

`.github/workflows/gate.yml` runs on every pull request and every push to main. Its jobs call `tools/gate_leg.sh`, which runs the same step of `tools/check.sh` that `make check` runs (the chain and bench legs with the arguments `all` gives them) and prints `gate: leg <name> exit <rc>, wall <s> s` after each.

| Job | Legs | Toolchains (read from the tree) |
|---|---|---|
| rust | fmt, clippy, deny | Rust of harness/rust-toolchain.toml |
| tree | pins, cite, jscpd, secrets, spec, tslint | Rust; Go and Node at the majors of docs/PROVENANCE.md section 1a |
| lean | lean, axioms, numbers, flow, sighash, arith, stack, crypto, seed, scripttests, txtests, flags, bytes, versiongate, eras, witnesses, eval, harness, chain, bench | Lean of lean/lean-toolchain (elan), Mathlib's oleans at lean/lake-manifest.json, Rust, Go, Node |

| record | none: `tools/check.sh record` reads the three jobs' logs with the verdict-line table and the writer of `make check` | bash and jq (the runner's) |

The record job's artifact `gate-record` is `docs/records/<stamp>-make-check-hosted.txt`; the workflow never commits it. Caches: `lean/.lake` and elan keyed on the toolchain, the manifest and the Lean sources, saved right after the lean and axioms legs pass, whatever the later legs do; cargo keyed on harness/Cargo.lock and the toolchain file. `CARGO_BUILD_JOBS=4`. The lean job's limit is 330 minutes; rust and tree 60 each, withheld-legs 5, record 15.

**The withheld legs.** A hosted runner holds the public tree and nothing else, so the legs that read a pinned upstream clone, the built reference or the box's bench baseline say SKIPPED BY NAME there, never a pass. Those reads, the node oracle and the Teranode instance (rules 10 and 17 keep the last two off every public runner) are listed by name in `tools/withheld_legs.txt`. The box runs the tripwire with the clones present and posts the commit status `box/withheld-legs` through `tools/box_status.sh`, which judges the box's record with `tools/withheld_legs.py --judge`: success when the record is GREEN on the box and every row the tripwire covers has its lines (built-reference, pinned-citations, rpc-contract-citations, box-walls); the node oracle and the Teranode instance are on demand, named in the status's own record, and not covered by it. The branch protection requires `box/withheld-legs` beside the hosted jobs.

**Reading a red.** Open the failed job. The job stops at the leg that failed; the last `gate: leg` line names it and the lines above are the leg's own output. `tools/check.sh <leg>` reproduces it on a machine with the same toolchains. A red `record` job with green leg jobs means a leg printed no verdict line of its own (RULES-TREE (28)); its log names the leg. A red or absent `box/withheld-legs` is the box's: its description names the box's record file, which the maintainers publish on request.

**Memory.** The axioms leg builds the kernel-checked stale run, which peaks near 29 GB (docs/records/20261014-061809-stale-cost-s1.md). A standard Linux runner of a public repository has 16 GB [LIT] (GitHub's documentation, 'About GitHub-hosted runners', the standard runners' table; read on the flip day), so the lean job adds swap up to 40 GB; the repository variable `GATE_LEAN_RUNNER` names a larger runner.
