## 1. What this is

The consensus rules of BSV script are defined by the C++ of the reference node at each release. A search of the public literature and repositories on 2026-10-06 (§9, with its terms and its hour; a record withheld from the public edition under a maintainer's open disclosure, counted in §7, carries the list) found no public, executable, machine-checked definition of those rules outside that code. This repository writes the rules down once, as an executable, machine-checked definition in Lean 4, and builds the harness that checks implementations against it. A disagreement is reported as a witness transaction and the rule it exercises, never as a sentence (`NORTH-STAR.md` §1, §2).

The object is the **script verdict** of the reference at one pinned release: bitcoin-sv (SV-node) **v1.2.3**, commit `6504a3aff65ba97c0f6c80962b033e35ecbfed4b`, tagged 2026-10-05T06:31:58Z (`docs/PROVENANCE.md` §1): the call the node makes once per input, `VerifyScript` inside `CScriptCheck::operator()` (`src/validation.cpp:2523–2543` at `6504a3af`; `docs/BLOCK-CONSENSUS.md` §1), decided from the unlocking script, the spent output's locking script, the flag word of the spend's and the coin's eras, and the transaction with its spent amount.

Four parts stand in the tree:

- **The semantics**, `lean/BsvScript/`: the number type, the machine, every opcode, the signature path, the transaction context, the flag and era model, the transaction-level gates, the properties; toolchain `leanprover/lean4:v4.34.0`, Mathlib `5ed2965256430c3649e86755f9576b54eca72435` (`docs/PROVENANCE.md` §1a).
- **The evaluator**, `eval/bsvs`: the same definitions compiled into a command-line tool that decides a spend from a transaction and its previous outputs, stamping its verdicts with the commit of its sources (`docs/STATE-OF-THE-WORLD.md` §3).
- **The harness**, `harness/`: generators, corpora carrying every engine's verdict beside the spec's, runners for bsv-rs, go-sdk, @bsv/sdk, GoBDK (the script library Teranode links), the reference node on the spec's own instances, and the Teranode instance (archived #41); the classifier tables under `harness/rules/`; the report writer `tools/conformance.py`.
- **The generated specification**, `spec/`: one page per opcode, the rule vocabulary with its corpus counts, every theorem with its explainer, written by `tools/specgen.py` from the Lean sources and refused by the tripwire when stale (111 opcodes, `spec/README.md`; 123 files up to date at `007664d4`, `docs/records/20261017-034122-make-check-box.txt`).

Two distinctions carry the design. **Consensus rules are the spec; policy limits are parameters**: every value the interpreter reads is listed in `docs/PARAMETERS.md` with its kind and its default in the reference and in Teranode, each cell cited to the source, and the semantics takes policy values as named parameters, never as rules (`NORTH-STAR.md` §2, constitution 01). And **the reference is a program**, which can be wrong or undefined; where it is, both readings are recorded and the maintainers rule (`NORTH-STAR.md` §6; §8).

## 2. Who it is for, and how a stranger checks it

For a node team that must match the reference, an SDK or wallet author whose engine must agree with the chain, a compiler author who wants a semantics to verify against, and an auditor. None of them has to trust this repository's sentences: each claim has a command or a record behind it.

**The Lean build and the axiom report.** `cd lean && lake build` builds the semantics sorry-free; `tools/axiom_check.py` runs `#print axioms` on every theorem listed in `lean/AxiomCheck.lean` and refuses any axiom outside `lean/AXIOMS-ALLOWED`, which holds Lean's three. The line of record, from the tripwire on the box at `007664d4` (`docs/records/20261017-034122-make-check-box.txt`):

> `axiom check: OK (1849 theorem(s), every declared theorem among them; the walk: 114 modules, 8297 theorems, 0 axioms, 0 compiler overrides, 0 outside; allowed = ['Classical.choice', 'Quot.sound', 'propext'])`

**The tripwire.** `make check` runs twenty-nine legs (`tools/check.sh:2`, the header names them) and writes a record naming the commit, the legs' verdict lines, the wall and the load. The newest GREEN record on the box, `docs/records/20261017-125850-make-check-box.txt`, names `commit: 77ab7d98` and reads `status: GREEN` and `make check: GREEN` in 80 s; its axiom, cite and `rules_check` lines equal those of the record at `007664d4` (`docs/records/20261017-034122-make-check-box.txt`, 81 s), which the figures below cite. **The harness, by one command.** `harness/run --impl <implementation> --corpus <corpus>` runs one implementation against one corpus and writes the report (`harness/README.md` is the manual). A stranger's dry run on `main` at `69d25ce`, by a reader that had seen nothing of this repository (`docs/records/20261005-231921-harness31-stranger.md`), answered YES for the documented command on go-sdk, @bsv/sdk and bsv-rs, and NO for all five implementations from a fresh worktree alone: GoBDK needs its clone and the built runner, SV-node a running node of the pinned release (archived #31).

**The records.** Every count a page quotes names a record that names the commit it measured (`CONTRIBUTING.md`, "Evidence labels"); they stand under `docs/records/`, whose index page is a record withheld from the public edition under a maintainer's open disclosure, counted in §7. ## 3. What is proven

The theorems are stated over the definitions the evaluator and the chain machine run: 1,849 on the axiom list, the `BsvScript` and `BsvChain` libraries with `lean/Bsvs/Trace.lean` (842, 1,003 and 4 by namespace, `lean/AxiomCheck.lean`), the figure of record being the axiom leg's line above; 1,849 carry a docstring of their own and are rendered with their explainers on `spec/theorems.md` (`spec/README.md` at `007664d4` names the three counting instruments). By family (the names are the Lean declarations; `docs/DESIGN.md` §9 states the properties):

- **Canonicality of script numbers** (`Numbers.lean`): `decode_encode`, `encode_minimal`, `castToBool_eq`, the width lemmas, and the v1.2.3 reader contracts `deserializeInt64_eq_decode`, `deserializeInt64_isSome_iff` and `deserializeInt64_min_iff`.
- **The version gate** (`Properties/Basic.lean`, `Properties/VersionGate.lean`): `gate_noninterference`: with the Chronicle marker set and a transaction version above 1 the verdict does not depend on the seven gated restriction bits, under the two side conditions found at the reference's ungated reads (P3); the four `verifyScript_*_off` theorems say it per flag, beside their ON-branch twins.
- **Parameter separation** (`Flags.lean`): `derive_consensus_separation` and `verifyScript_consensus_separation`, the block word and the block verdict depending only on the consensus fields of a node's configuration (constitution 01 as a theorem); `blockScriptFlags_policy_off`, the block word never carrying a policy flag; `verifyScript_relay_block_version2`, the relay and block words judging a version-2 spend alike post-Chronicle but for DISCOURAGE_UPGRADABLE_NOPS.
- **Phase crossing** (`phase2_stack_mem_only`): the locking phase depends on the unlocking phase only through the main stack and the memory counter.
- **The eras and P2SH** (`Properties/Eras.lean`, `Properties/P2SH.lean`): the era function total and monotone with its boundaries (`protocolEraOf_total`); the block word's P2SH, DERSIG and CLTV bits entering at the heights the code tests (`flagWord_block_p2sh`); P2SH disabled for a post-Genesis coin (`verifyScript_p2sh_disabled_postGenesis`).
- **Two facts of the loop**: `opreturn_suffix`, from a top-level `OP_RETURN` onward the loop never reads the bytes after it; `checksig_empty_sig`, an empty signature never invokes the signature predicate.
- **The compiled machine refines the definition** (`Eval.lean`): `verifyScript_eq_I`, a `@[csimp]` lemma proven through `opExecI_refines`, ties the array machine the binary runs to the list definition the theorems speak about; 36 such lemmas exist (`docs/HYPOTHESES.md` §3).
- **The kernel-evaluated sample** (`Properties/KernelSample.lean`): 25 fixed vectors, each decided by `decide +kernel` on the definitions with no compiled code entering; the compiled evaluator runs the same list in the flow leg and exits 1 on any disagreement. Evidence at 25 points about the compiler, not a proof of it.
- **Resources, widths and hooks** (`Properties/Resources.lean`, `Widths.lean`, `Hooks.lean`): the op-count and memory invariants of the loop, the opcode widths, the sigop count on every path; **determinism**, `Eval.verifyScript_deterministic`, carries nothing beyond the function being a function.

A theorem covers the definition; the corpus covers the compiled code. The refinement lemma and the kernel sample tie the two; the gap between them is named next.

## 4. What is assumed

`docs/HYPOTHESES.md` is the page of record for the trust boundary; `docs/SECOND-FORMALIZATION.md` §1 names the trusted items T1 to T8 with the evidence standing for each:

1. **The transcription of the interpreter** (T1): one reader's rendering of `src/script/interpreter.cpp` and the files of `docs/PROVENANCE.md` §2 into Lean, every rule citing its line; the evidence is the reference's own verdicts (§7).
2. **The transcription of the signature path** (T2): the point decoding, the lax DER parser, the normalization of `s` and the ECDSA equation are transcribed from the vendored libsecp256k1 and `pubkey.cpp` at the pin; the field and group arithmetic computes the same values by other means. There is **no axiom** for signature verification: the equation is an executable definition (Q9, ruled (A) by the maintainers on archived #38, 2026-09-22; `docs/HYPOTHESES.md` §2). The evidence: 1,340 constructed ECDSA cases, the curve's known facts, the lax parser's long forms, eight mainnet inputs, the node's agreement on the crypto corpora (`docs/HYPOTHESES.md` §1), the vector file's identity at the 0.3.30 pin (`docs/records/20261005-225025-ecdsa-identity-0.3.30-s3.md`).
3. **The compiled evaluator** (T3): the Lean compiler, the C toolchain and linker, the runtime, the compiler's use of the `@[csimp]` lemmas, and the CLI's own readers and runners that no theorem covers (`Run.paramsFor`, `Run.combine`, `Run.txGate` among them). The binary can abort where the definitions are total: a resource wall is no verdict (`docs/HYPOTHESES.md` §3).
4. **The Lean kernel and its three axioms** (T4): `propext`, `Classical.choice`, `Quot.sound`.
5. **The statements** (T5): that each theorem says what its explainer says. The three-lens review of archived #32 is this program's substitute for an external reviewer; the public is the audit after v1.0 (`NORTH-STAR.md` §5).
6. **The harness glue** (T6): the entry readers and the adapters; a one-sided error appears as a divergence, never as silent agreement.
7. **Coverage** (T7): the inputs no corpus reaches; `corpus/INDEX.md` §1 lists every generator with its seed.
8. **The reference itself and the pin.** The reading of record at v1.2.3 is a defined refusal (`int_serialization.h:61–118`, `script_num.cpp:80–91` at `6504a3af`); the previous pin's reading and its measurements are recorded in material withheld from the public edition at the maintainers' request (group `d8-node-team-discretion`).

## 5. What is not claimed

This list is the page's heart; `docs/HYPOTHESES.md` §6 carries its summary. Two of its items moved when S6, the transaction state machine (archived #58), landed: since S6 (2026-10-14) the executable base covers the UTXO set, the mempool as policy parameters, block validity, the chain with undo and most-work selection, merkle inclusion and the derived status function, judged by the pinned node per scenario row (`README.md`, "What stands", and `docs/records/20261018-133547-make-check-box.txt`; the tracker's milestone "S6 · The transaction state machine", archived #58 to #77; `docs/DESIGN-S6.md`). Item 1's finality and sequence locks and item 2's block-level rules moved there, as each item says; what stays below is what the script verdict still does not claim. S7, the node beyond the chain (archived #78 to #86, the tracker's milestone "S7 · The node beyond the chain"), moves no item: none of the list's nine items concerns P2P, persistence, events, RPC or the wire formats, and S7's nine issues are closed on the tracker, the last on 2026-10-15 (`README.md`, "What stands").

1. **The transaction-level gate outside the CLI's verdict.** The spec's verdict is the script verdict. The transaction's own validity (`src/validation.cpp:520–640`) is modeled in `BsvScript.TxRules`, standardness and the mempool's caps in `BsvScript.Standard` and `BsvScript.TxPolicy`, and the CLI applies `Run.txGate` before the scripts; but that gate is CLI code no theorem covers (`docs/HYPOTHESES.md` §3), and finality and the sequence locks are outside the script verdict (`docs/DESIGN.md` §5.5): the class `tx.finality.out-of-scope` is the node refusing two `corpus/tx` entries the CLI's verdict does not judge (`docs/records/20260928-155752-road-a4-s3.md`). Finality and the sequence locks moved to S6: `lean/BsvChain/Finality.lean` defines them for the state machine (`docs/DESIGN-S6.md` §4.1), so they are no longer not-claimed at the chain layer; the CLI's script verdict still does not judge them.
2. **Block-level consensus, at the script verdict.** `docs/BLOCK-CONSENSUS.md` (archived #36) names every rule the node applies to a transaction and a block beyond the script verdict, each with its source lines and its kind, among them a third kind by the maintainers' ruling of 2026-10-05, a block-validity mechanism driven by an operator's list. These rules moved to S6: that page's header gives them to the transaction state machine (`docs/DESIGN-S6.md`), whose guarantee is the maintainers' ruling S6-1 of 2026-10-12, inclusion as a theorem over the machine (`docs/DESIGN-S6.md` §8); they are no longer not-claimed for the chain layer, and the script verdict still leaves them out.
3. **The pre-Genesis rows until archived #27's record.** `corpus/eras` holds 74 rows, 42 of them with a pre-Genesis spend or coin (`corpus/INDEX.md` §1, the eras row); the node decided all 74, and the report's sv-node table has 74 of 74 agreeing with the spec in both columns (`docs/CONFORMANCE-2026-09-27.md` §1 at `accb04a`, its manifests replayed by `docs/records/20261006-022137-make-check-box.txt`; the run, `docs/records/20260924-030828-svnode-record-s3.md`). The pre-Genesis rows are the node's verdicts alone. archived #27 closed on its record runs (2026-09-24 and after): every generated corpus is recorded against the node's two instances, and the recordings are replayed by the tripwire's harness leg at every landing (`rules_check`, 45 manifests at `fd88a35`; 100 at `007664d4`, `docs/records/20261017-034122-make-check-box.txt`); the pre-Genesis rows carry no claim beyond the node's verdicts on them.
4. The reading of record at v1.2.3 is a defined refusal (`int_serialization.h:61–118`, `script_num.cpp:80–91` at `6504a3af`); the previous pin's reading and its measurements are recorded in material withheld from the public edition at the maintainers' request (group `d8-node-team-discretion`).
5. **Termination is definitional, not a theorem.** Every recursion of the semantics is structural or carries its `termination_by` measure, and none is `partial`; the kernel checks that at each definition. No theorem states "the evaluator terminates", none will, and a page that calls termination a theorem is wrong (`docs/HYPOTHESES.md` §4). Beside it stand the three axioms of §4, item 4: these are what the machine-checked claims rest on.
6. **The Teranode and SDK columns are conformance runs at named pins, not endorsements.** A column says what one build at one pinned version answered on the named corpora in two flag words (`spec`, the block word; `spec-mempool`, the relay word), every disagreement classified; nothing about another version or about fitness.
7. **Everything `docs/HYPOTHESES.md` §3 lists as outside Lean**: the harness, the engines' verdicts, the node oracle, the compiled evaluator's toolchain.
8. **That the reference is correct.** The spec earns its authority by conformance runs; if it and the reference disagree, the chain follows the reference until the humans decide (`NORTH-STAR.md` §6).
9. **Priority.** §9 names the public work this was checked against and states a dated observation, not a claim.

## 6. The method

**Every rule cites the reference at the pin** (`NORTH-STAR.md` §2, constitution 02); a rule written from memory is a draft. The cite leg (archived #43) re-reads every file:line citation of `lean/` and `docs/` against the pinned sources on every tripwire run and refuses a moved line; at `007664d4` it reads GREEN, 5,685 citations anchored and holding at the pin, MOVED 0, closed history not checked (`docs/records/20261017-034122-make-check-box.txt`).

**The reference is subject to review under the errata rule (§8).** The reading of record at v1.2.3 is a defined refusal (`int_serialization.h:61–118`, `script_num.cpp:80–91` at `6504a3af`); the previous pin's reading and its measurements are recorded in material withheld from the public edition at the maintainers' request (group `d8-node-team-discretion`).

**The corpus is the judge** (`CONTRIBUTING.md`, "Report a divergence"): the spec is wrong until the corpus agrees with the reference. The node oracle is the spec's own instance of the pinned build, run twice: with every policy cap zeroed (the `spec` column; Q6 answered from source: the policy path then evaluates under the consensus limits, `docs/DESIGN.md` §9) and at the node's default policy (the `spec-mempool` column); the block road submits transactions in blocks on a private chain (`docs/STATE-OF-THE-WORLD.md` §3). Nothing is broadcast (`CONTRIBUTING.md`, "What never enters").

**Divergences are witnesses**: the smallest transaction that exhibits one, the rule it exercises, the citation that decides it. The classifier is data (`harness/rules/*.json`, D83), the report is generated from the manifests and the tables, and a divergence no table explains turns the tripwire's harness leg RED.

**Consensus and policy are told apart by name** (constitution 01): the census is `docs/PARAMETERS.md`, the derivation is `Params.derive`, and `derive_consensus_separation` is its theorem. **Every claim carries its label or names its record** (`CONTRIBUTING.md`, "Evidence labels"). **Nothing of the maintainers' other programs enters this tree** (constitution 05): `tools/mechanism_check.sh` greps the sources and the corpora for their vocabulary and their bytes; a sibling consumes the shim as a tool, at most.

## 8. The errata of the reference (`CONTRIBUTING.md`, "Consensus and policy stay apart")

Where the reference disagrees with its own documentation, or a downstream build names the same thing differently, the spec records both with citations and the maintainers rule; the record is the deliverable. The three the tracker names on archived #33, each carried by `docs/PARAMETERS.md` §4 or `docs/DESIGN.md` §11:

1. **`stopOnFirstInvalid`: the help text against the code.** The `verifyscript` RPC's help text says the argument defaults to **true** (`src/rpc/misc.cpp:568`); the code makes it **false** when the argument is absent (`src/rpc/misc.cpp:609–615`). Booked on archived #6. Disposition: the code's behaviour is the node's; the harness passes the argument explicitly on every call (`docs/DESIGN.md` §7), so no harness verdict turns on the default. No ruling is recorded on archived #6 (its comments read by REST on 2026-10-06).
2. **P2SH's activation: the comment's 173,805 against the code's 173,806.** The block word tests P2SH against the chain tip's height: `GetBlockScriptFlags(config, tip)` (`src/validation.cpp:2973–2982`) is called with the block's parent (`src/validation.cpp:3473`) and `src/verify_script_flags.cpp:39` tests `height >= p2shHeight`, so P2SH enters the block word of block **173,806** on mainnet, while the comment above the test says "P2SH became active on Apr 1 2012, block height 173,805" (`src/verify_script_flags.cpp:38`; `p2shHeight` 173,805 at `src/chainparams.cpp:28`). The spec transcribes the code (`flagWord_block_p2sh`, `Properties/Eras.lean`); the replay of block 173,805, the one block whose inputs the two readings could judge apart, read its 106 transactions and 256 inputs and found no P2SH-shaped output spent in it, so on mainnet's history at the boundary the two readings give the same verdict (`docs/records/20260928-115150-replay-173805-s3.md`); a constructed block at that height would still tell them apart, and the record covers mainnet only. Recorded on archived #20 for the maintainers' ruling; no ruling is recorded there (its comments read by REST on 2026-10-06).
3. **GoBDK's `SCRIPT_ERR_ILLEGAL_RELAX` against the reference's `SCRIPT_ERR_ILLEGAL_CHRONICLE`.** At the ordinal of bitcoin-sv v1.2.2's `SCRIPT_ERR_ILLEGAL_CHRONICLE` (`src/script/script_error.h:80`, the string at `src/script/script_error.cpp:100`), the Go binding of the script library Teranode links names the code `SCRIPT_ERR_ILLEGAL_RELAX` (`bdk/module/gobdk/script/scripterror.go:86` at `cdfa7814`): the same enum, two names, because BDK compiles against an external bitcoin-sv tree (`core/setting-bitcoin.cmake:9–11`). Disposition: the harness compares reasons by the `SCRIPT_ERR_*` name at the pin and records the tree GoBDK was built from (`docs/PROVENANCE.md` §1); a reason difference is never a verdict difference.

## 11. How to report a divergence or a security concern

**A divergence.** Reproduce it as the harness would see it: a transaction, its previous outputs with their heights, and the implementation's verdict beside the spec's (`eval/bsvs`; the entry format is `docs/DESIGN.md` §6). If a class on the report already names it, `tools/witness.sh <id>` replays the smallest witness. Open an issue with the entry on the public repository's issue tracker. A divergence between the spec and the reference is a spec bug until a human proves otherwise from source (`CONTRIBUTING.md`, "Report a divergence").

**A security concern.** A divergence that lets a transaction be accepted by one implementation and refused by another is a chain-split or a theft risk for whoever runs the weaker side. Send it privately through the public repository's private vulnerability reporting form (the "Report a vulnerability" button under its Security tab), not on the issue tracker. The program's own findings follow the same discipline (§7, the withheld classes).
