**What the stack samples say (`sample <pid> 3` at 5 s into the run; the "Sort by top of stack" leaves, in `bsvs`):**
- `pushes` 400 KB: `l_List_lengthTR___redArg` 1,394 of 1,399 samples, `List.takeTR.go` 5. The parser's push check
  `getOpTail` (`lean/BsvScript/Machine.lean`: `if body.length < n then none else some (body.take n, p + n)`) walks the
  REST OF THE SCRIPT for every push instruction: the cost is pushes × remaining bytes, quadratic in the script.
- `number` 200 KB: `__gmpn_divrem_1` 742, `__gmpn_copyi` 692, `__gmpn_rshift` 57; `lean_nat_big_mod` on the stack.
  The encode side: `Numbers.magBytesFuel` (`(m % 256) :: magBytesFuel fuel (m / 256)`, the fuel the number itself) does
  one bignum division and one bignum predecessor per BYTE of the result.
- `number` 400 KB: `__gmpn_copyi` 923, `__gmpn_mul_1` 325; `lean_apply_4` on the stack. The decode side:
  `Numbers.beNat` (`foldl (fun acc b => acc * 256 + b) 0`) does one bignum multiplication per byte of the operand.
Both number-side loops are one operation of the number's size per byte: quadratic time; and the resident set grows
with the byte count (4.74 GB at 50 KB, over 8 GB before 100 KB) `[M]`, so the intermediate bignums are held, not
released, while the loops run `[D on M]`.

**The reading.** The READER (`Bsvs.Corpus.hexBytes` → `Tx.hexDecode` → `List Nat`, then the push into the machine)
is linear and small: 2.2 MB in 0.30 s at 0.49 GB, about 200 bytes of peak per script byte `[M]`. The walls are two,
both in the MACHINE: (1) the parser's per-push length test, the wall for a push-heavy script (an emitted verifier);
(2) the number decode and encode on a large NUMBER, the wall for a literal number read or written by an arithmetic
opcode (the Finding's 750 KB entry was of this kind: `OP_LSHIFTNUM` on a literal operand; the in-script twin
`corpus/gen` builds runs the same encode, and its 12–19 GB peak in `docs/records/20260924-040437-gen-first-cut-s3.md`
is this loop). The Finding on #35 (5807176756) attributed the death to the reader: a `**Correction.**` on #35 and #45.
