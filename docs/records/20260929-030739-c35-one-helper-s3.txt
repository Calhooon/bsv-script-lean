WHY ONE TRAP NAMES BOTH (zsh 5.9, the Studio's and the box's; [M] on the Studio, 2026-09-29 01:36 UTC):
   /bin/zsh -f -c 'trap "echo the trap EXIT ran" EXIT; TRAPEXIT() { echo the TRAPEXIT function ran; }; exit 0'
     -> the TRAPEXIT function ran
   /bin/zsh -f -c 'TRAPEXIT() { echo the TRAPEXIT function ran; }; trap "echo the trap EXIT ran" EXIT; exit 0'
     -> the trap EXIT ran        (and `functions TRAPEXIT` finds it gone)
   zsh's `trap ... EXIT` and a TRAPEXIT function are ONE trap: the last one set replaces the other. The plan's tools/lean_lock.sh
   (59ca01f4) defines TRAPEXIT at its top level when sourced under zsh (its line 60), and the helper's usage is `trap
   box_leg_release EXIT` at the caller's script level (its line 50): a zsh script that sources lean_lock.sh and then sets that trap
   loses the Lean slot's release at exit, and one that sets the trap and then sources lean_lock.sh loses the leg lock's.
