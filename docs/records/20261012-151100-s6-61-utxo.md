## Findings and differences from the note

**Finding (rule 15): unavailable-input reason belongs to the caller.**
The brief attaches `bad-txns-inputs-missingorspent` to `checkTxInputs`.
At the pin, `Consensus::CheckTxInputs` returns [SRC] code 0, empty reason,
and debug text `Inputs unavailable` (`src/validation.cpp:2557–2559`). The
block caller returns [SRC] code 0x10 and the named reason
(`src/validation.cpp:3326–3331`). Both layers are modeled, and both missing
and spent rows exercise both layers. The debug string is not substituted
for the reject reason. The dated DESIGN §9 sentence records the distinction.

**Finding (rule 15): AddCoin's stored-height rule differs from its comment's
suggestion.** [SRC] `src/coins.cpp:54–64` says the height should be compared
against the active chain, then implements Genesis selection from the raw
stored coin height. `createdOutputs` models that code, even for
`MEMPOOL_HEIGHT`. Input script selection separately substitutes the active
tip's successor (`src/validation.cpp:2667–2674`). The source-derived
`outputs/mempool-stored-height` row probes the stored-height rule; the
`coin-era` rows probe consumption. The former is a synthetic UpdateCoins
height probe, not a claim about a complete mempool admission. #62 can reuse
`checkTxInputs` and `updateCoins` separately when its check height and stored
height differ. No source comment is treated as executable behavior.

[M] Non-coinbase AddCoin overwrites of live entries throw a logic error at
[SRC] `src/coins.cpp:386–401`; `applyTx` totalizes it with code [D] 0 and the
exact exception text, rather than claiming a new node rejection code.
Coinbase overwrites are permitted at [SRC] `src/coins.cpp:560–565`.
The undo vector retains spent coins only, not overwritten output history
([SRC] `src/undo.h:80–83`). The one-transaction undo theorem therefore assumes
no eligible output key exists in the remaining map after input erasure. On
live UTXO sets this is the pin's no-live-overwrite condition; for raw caches
with spent sentinels it also excludes replacing an unspent-in-this-call
sentinel entry. The separate coinbase overwrite row demonstrates undo loss.
The pairing of spent coins with input-derived keys is a lossless presentation
of the pin's aligned vector, not a snapshot of the original set.
