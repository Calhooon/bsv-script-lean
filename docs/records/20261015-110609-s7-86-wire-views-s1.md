**Finding (draft, #86, the engines re-order a BUMP's level).** [X] WhatsOnChain serves 21 of the 22 mainnet
BUMPs of this corpus (all but the lone transaction of block 1) with level 0 in descending offset order
(`bump-002` to `bump-022`; the same BUMPs inside its BEEFs, `beef-002` to `beef-022`, and the Atomic BEEFs built
from them; and `bump-034`, a compound BUMP's four-leaf level 0 reversed). bsv-rs 0.5.0
`src/transaction/merkle_path.rs:301` ("Sort leaves by offset"), go-sdk v1.7.2 `transaction/merklepath.go:266`
("Sort each of the levels by the offset") and @bsv/sdk 3.0.0 `packages/sdk/src/transaction/MerklePath.ts:148`
(ts-stack `4d0ea63c`; "Sort the array based on the offset property") sort each level on reading, as BRC-74's own
reference parser does (0074.md:300), so their writers do not give the file back; the projections and the view are
unchanged on every such row. BRC-74 states no order for a level's leaves. The spec's codec keeps wire order
(`bump_encode_decodePrefix`), so one BUMP value has one encoding. A consumer that hashes or signs a BUMP's bytes
after an SDK round trip signs different bytes than it received. Not a rule; a client-format observation.

**Finding (draft, #86, the readers' leniency).** [X] Each witness of class `codec` above is a byte string the
spec refuses by the BRC's table and an engine reads, or the reverse: a flags byte `04` (0074.md:73-77 names
00, 01, 02; all three read it as a hash, `bump-028`), a flags byte `03` with no hash after it (`bump-027`: all
three read it as a duplicate; bsv-rs and @bsv/sdk write it back as `01`, go-sdk as `03`), a trailing byte after a BUMP (all three), after an EF (bsv-rs), after a
BEEF or Atomic BEEF (go-sdk); a non-canonical offset (bsv-rs, go-sdk; ts-sdk's strict reader refuses it, as the
spec does); a tree height of 65 (go-sdk; 0074.md:51 says max 64); a truncated last hash (go-sdk reads a short
final hash with `reader.Read`, not a full read, `merklepath.go:253`); a "Has BUMP" byte `02` and a format byte `03` (bsv-rs, ts-sdk;
0062.md:68 and 0096.md:58 name 00/01 and 00/01/02); and in the other direction go-sdk refuses at parse a BUMP

refuse. Each row is a witness with its bytes in `corpus/wire/`.
