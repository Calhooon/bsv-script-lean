## What the run corrected (CLAUDE.md rule 9: the original sentences are gone)

1. **The node does not enforce BIP68 after Genesis `[SRC]`.** `StandardNonFinalVerifyFlags` sets `LOCKTIME_VERIFY_SEQUENCE` only while Genesis is not active (`src/policy/policy.h:248–256` at v1.2.2); the block path takes those flags at `validation.cpp:3465–3469`, the mempool at `:1101`; `CalculateSequenceLocks` enforces nothing without the flag (`:273–280`). The corpus's `tx/sequence/bip68-age` (`tx-00019`) spends at 620,600, after Genesis: the node accepted it in the block and in the mempool (the previous run of the same code, 22:15 UTC, first showed it), agreeing with the spec. Its note, which said the node refuses it on both roads, is re-written; so are the two notes that credited BIP68 with a met lock (`tx/sequence/blocks/below`, `tx/sequence/time/below`); the class text is re-cut; `docs/records/20260926-215135-tx-families-s3.md`'s sentence naming the row among the refused ones is replaced there. The ENFORCED case is a new entry appended last so no earlier id moves: `tx-00037` `tx/sequence/pre-genesis/bip68-age` (a coin mined at 605,000, the input's sequence 5,001 blocks, spent at 610,000: the lock's last invalid height 605,000 + 5,001 − 1 = 610,000 is not below the block's, `:257–336`), refused by the block (`bad-txns-nonfinal`) and by the mempool (`non-BIP68-final`) exactly as that arithmetic says.
2. **After Genesis a non-final transaction is ACCEPTED by the mempool, into the non-final pool `[SRC]`.** `ContextualCheckTransaction` returns without a DoS off the block path once Genesis is active (`validation.cpp:5936–5941`), and the transaction goes to the non-final pool (`:912–926`, `:1108–1124`). `tx-00010`'s mempool verdict is therefore valid, as the spec's; its note said the mempool refuses it.
3. **The mempool's reason `non-BIP68-final`** (`:1203`) joined `svnode_codes.rs`'s `TX_TABLE` (now 37 reasons), with its classifier row (`spec-mempool`, `family_contains: bip68`).
