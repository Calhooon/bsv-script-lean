[SRC] New reader refusals, from the tagged reader source linked above:

| refusal | condition and location |
|---|---|
| `UnprovenCoinbase` (`Kind` and `Reason`) | An unproven coinbase, at its transaction's leading byte, before the no-output check. Proven coinbases remain allowed. |
| `NullOutpoint` (`Kind` and `Reason`) | A null outpoint in an ordinary input, at that input's previous txid. |
| `DuplicateInput` (`Kind` and `Reason`) | A repeated input in one transaction, at the repeated input's previous txid. |
| `ValueOutOfRange` (`Kind` and `Reason`) | An output value or running output sum outside MoneyRange, at the offending value field. |
| `InputValueOutOfRange` (`SpendRefusal`) | An input value or running input sum outside MoneyRange, at the input that crosses the bound. |
| `P2shOutput { vout }` (`SpendRefusal`) | An exact 23-byte P2SH-shaped output in an unproven transaction when the next block is after Genesis, at its value field. Without a tip, this era check assumes after Genesis. Near-shapes and proven transactions keep their previous behavior. |
| `NonFinal { lock_time }` (`SpendRefusal`) | Supplied next-block context fails `IsFinalTx`, at the transaction's leading byte. Time locks after CSV use tip median time past; before CSV they need candidate block time. |
| `PrematureCoinbase { height }` (`SpendRefusal`) | A verified coinbase would be fewer than 100 blocks old at the next block, at the spending input. Verified coinbase heights survive retention and cursor round trips. |
| `Unverifiable`, check `MiningCheck::Finality` | Nonzero lock time with a non-final sequence lacks a tip, or the required pre-CSV candidate time is missing. Both `Verdict` and fold `Stop` carry the decline with its offset. Zero lock time or all-final sequences need no tip. Missing context is never guessed into `Invalid` or `NonFinal`. |
| `Unverifiable`, check `MiningCheck::CoinbaseMaturity` | The verified coinbase spend needs a tip to establish maturity and none is supplied. |

The four byte refusals apply in the decoder and hand-built fold, including
`structure_only`; output and ordinary-input checks also apply with a BUMP
index. The order is coinbase, no inputs, no outputs, output values, then
null/repeated outpoints in input order. Contextual spend checks apply only
in full mode to unproven transactions. Cross-transaction respends remain
`OutputNotAvailable`; the existing `ParentIsTxidOnly`, `Script` and
`CreatesValue` cases otherwise remain. These are described here as refusals;
this lane adds no rule or policy classification. This direct-Spend retally
does not exercise the new streaming behavior.
