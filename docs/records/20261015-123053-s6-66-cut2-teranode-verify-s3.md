## Work item 5 (#90 and #91): exactly what is missing

[D] The brief's work item 5 asks for #90's scenario `corpus/scenarios/2026-10-14-conflicting-spends-order.md` and #91's refusal pair run through both oracles "if the road reaches them," or an exact statement of what is missing. The road does not reach them. The scenario file itself states that `submitConcurrent`, the `*_one_of` keys and `fork_after: "initial"` "are new to this format: the runner's support for them is owed by #66," and "Nothing here was run." The missing pieces, each a runner-core item, are:

1. **No family handler dispatches `conflicting-spends-order`.** `harness/src/scenarios/mod.rs` `family_run` dispatches only `mempool`, `finality`, `block`, `utxo`, `chain`, `oracle`, `eras`, `frozen`. The #90 scenario's witnesses are `BsvChain.Teranode.{accepted_eq_mempool, concurrent_both_refused, reorg_keeps_differ}`; it needs either a new family handler or wiring into an existing one, with the second-oracle expectation objects (`store_mempool`, `spenders`) read through `lean/BsvChain/Teranode/Spend.lean` as the scenario specifies.
2. **`submitConcurrent` is unimplemented.** No step-action type submits a set of transactions together; the runner's core has only sequential submission (`core.rs` `submit`). The concurrent primitive needs a definition on both oracles (a concurrent batch into the reference and into Teranode's validator mempool path) and a chosen observation point, because which conflicting transaction wins is not deterministic.
3. **The `*_one_of` expectation keys are unimplemented.** No comparator accepts any one of a set of outcomes; the concurrency variant needs it, since the earliest-seen winner under concurrent arrival is not fixed.
4. **`fork_after: "initial"` is unsupported.** The one `fork_after` reader, `harness/src/scenarios/intake.rs:499`, matches the value against a step `id` in the primary steps and errors `missing checkpoint` otherwise; "initial" is not a step id, so a variant forked before `s1` has no handler. (#90 is not an intake scenario; this reader is the only `fork_after` in the runner and would need the "initial" case or a #90-specific equivalent.)
5. **#91's refusal pair has no scenario file.** `corpus/scenarios/` holds no refusal-pair file; #91 is named only in `corpus/teranode/map.json`, `docs/STATE-OF-THE-WORLD.md`, `docs/PLAN-2026-10-14-WAVES.md` and `docs/PROVENANCE.md`. There is nothing to run for #91 until its scenario is written.
