**What it defines and proves** (namespace `BsvScript.Gadget`, over `BsvScript.Machine` alone):

| name | kind | what |
|---|---|---|
| `GOut` | inductive | a fragment's outcome inside a larger script: `next` (its end reached), `stop` (a top-level `OP_RETURN` after Genesis ended the whole script, `858–861`), `err`, `undefined` (Q7), `unimpl` |
| `run exec env g tail st` | def | `Machine.loop`'s step over the fragment `g`, without the end-of-script test (`1828–1830`); `tail` is handed to the step only as the rest of the whole script, which `OP_CODESEPARATOR` keeps (`1445–1448`) |
| `GOut.toLoop` | def | the end-of-script reading of an outcome (`loop`'s `[]` case) |
| `loop_eq_run` | theorem | `Machine.loop exec env s st = (run exec env s [] st).toLoop`: the API runs the semantics' own loop, never a second machine |
| `framed g` | def | every instruction of `g` parses inside `g` |
| `getOpTail_append` | theorem | a parse inside a prefix is the parse inside the whole, and consumes at most the prefix (`script.h:163–198`) |
| `run_append` | theorem | for a framed `g`: `run exec env (g ++ h) t st = (run exec env g (h ++ t) st).andThen (run exec env h t)`, composition by concatenation |
| `Triple exec env P g Q` | def | from every state satisfying `P`, whatever follows, `g` runs to its end in a state satisfying `Q` |
| `Triple.seq` | theorem | a framed `g` with `Triple P g Q` and `Triple Q h R` gives `Triple P (g ++ h) R` |
| `Triple.conseq` | theorem | a stronger precondition and a weaker postcondition keep a triple |
