## The design

| part | what |
|---|---|
| the SDK column (item 1) | after `run_svnode`, per engine of `FUZZ_ENGINES` (`go-sdk ts-sdk`): `run_engine --engine <engine> --corpus <batch>/corpus/seed.jsonl --spec <batch>/spec.jsonl --witnesses <batch>/engines --dump <batch>/engine-<engine>.dump.jsonl`, no `--record`, the runners as they stand (`harness/target/engines/gosdk-runner` or `GOSDK_RUNNER`; `harness/engines/ts/runner.mjs` with its `node_modules` and node 22 by `tools/node_bin.sh`). Its outputs stay in its own layout, `<witnesses>/<engine>/<corpus>.jsonl` and `manifest.json`: the batch's corpus directory is named `corpus`, so `engines/<engine>/corpus.jsonl` (no rename); `tools/fuzz_batch.py` reads the counts from the manifest's `corpus` key, the verdict from `run_engine`'s own GREEN/RED line, the divergent cells from the dump. An engine whose `run_engine`, runner, adapter install or node 22 is absent is `SKIPPED(<reason>)` on the batch line; `run_engine` stopping without a manifest or a verdict is `FAILED(exit-<n>)`; neither is counted as agreeing |
| the SDK rows | in the harness's witness shape, as the node's rows (one builder, `witness_row` in `tools/fuzz_batch.py`), in `corpus/fuzz/<date>-<engine>.jsonl`: one row per divergence class new to the campaign (a column and a rule of `harness/rules/<engine>.json`), at `run_engine`'s own witness entry of the class (its smallest), with the class's cell count and its leading 20 entry ids under `fuzz`; `unexplained` writes every new spend (20 a batch at most, `FZ_ROW_CAP`). Why a row per class and not per cell: at the pins ts-sdk's `default/spec` column diverges on some 1,460 cells of each 51,000-case batch under one ruled class (`flags.policy-as-consensus`, the dry run below), so a row per cell would add some 1,500 rows of one class to the repository every batch. A batch that writes an SDK row keeps `run_engine`'s outputs, still in its layout, under `kept/batch-<n>/engines/` of the state directory |
| the per-family salted seeds (item 5a) | `seed_gen --family F` (`harness/src/bin/seed_gen.rs` `draw`): one family's stream alone under a seed, the same generators and version-1 twins; a mutation stream draws its bases from the mix and emits only the mutants. Without the flag the stream is the mix byte for byte as before: [X] `seed_gen --seed 0xca1872e03c5cb8c8 --count 50000` gives sha256 `68ab07dc2788ab8f…` (the campaign's batch 1, record `20261015-132239-fuzz-campaign-s3.md`) from the campaign's binary and from this lane's, manifests equal. Batch n's family F runs under S xor `0x` + the leading 16 hex digits of sha256(`spec-fuzz-campaign family F`), S the batch seed as before; the counts are seed_gen's mix per hundred of `FUZZ_BATCH` (arith 55, nonmin 10, size 8, depth 6, num2bin 6, mutation 15: 27,500 / 5,000 / 4,000 / 3,000 / 3,000 / 7,500); every part's seed is on the batch line (`seeds=`) and in every row (`fuzz.part_seed`, `part_count`, `orig_id`) |
| the replay (item 5b) | `tools/fuzz_compose.py` reads every row of `FUZZ_REPLAY` (default the campaign tree's `corpus/fuzz`, read only) and places one case per distinct spend (its tx, prevouts and params) after the smoke and before the fresh cases, its `expect` cut to seed_gen's bsv-rs verdict. The batch line's `replay=rows:R,still:S,fixed:F,unrun:U` tallies each replayed row's own cell: diverging again, agreeing now, or not run (its engine skipped or failed). A cell whose spend and column already hold a row is counted and never written again |
| the per-family counts (item 5c) | `families=smoke:..,replay:..,arith:..,…` (cases per part) and `divergent_by_family=` (divergent cells per part, all engines' columns together) on every batch line |
| the smoke prefix (item 5d) | the leading `FUZZ_SMOKE` (1,000) cases of the bench leg's fuzz smoke at the campaign tree's commit: `seed_gen --seed 0x<the commit's leading 16 hex digits>`, the seed `tools/bench_leg.sh` takes from `HEAD`, as the corpus's head. [X] At `e62b9482` (`0xe62b94827c99e6c3`) the leading 1,000 entries of `--count 50000` are byte-identical to `--count 1000`, and the composed smoke part equals them with only the ids prefixed (`smoke-`) |
| the walls | `walls=gen:..,spec:..,sv-node:..,go-sdk:..,ts-sdk:..` seconds per stage on the batch line (`e62b9482`) |
| a fix | the landed loop copied a divergent batch's run_svnode witnesses from `<batch>/w/sv-node/seed.jsonl`, a path run_svnode never writes (it names the file after the corpus's directory, `corpus`, `harness/src/bin/run_svnode.rs:817`); the copy now reads `<batch>/w/sv-node/corpus.jsonl`, and is made only by a batch that writes a node row. No batch had a divergent node cell, so nothing was lost |

## What changed in the batch and daily lines

- The batch line gains `go_sdk=` and `ts_sdk=` (`GREEN|RED,agree:..,divergent:..,unexplained:..,undecided:..,aborts:..,rows:..`,
  or `SKIPPED(<reason>)`, or `FAILED(exit-<n>)`), `families=`, `seeds=`, `replay=`, `divergent_by_family=` (when any) and
  `walls=`; `count` is the fresh cases, `spends` the whole batch (smoke, replay, fresh); `divergent` stays the node's
  cells; `witnesses=` names every day file the batch wrote. The started line names the engines' readiness and the
  sha256 of `run_engine` and the go-sdk runner when present.
- The daily line gains `; replay still P fixed Q unrun Z` and, per engine of the day's lines, `; <engine> ran N (red R)
  skipped K failed F agree A divergences D (unexplained U) rows W`; `witnesses` names every day file
  (`<date>.jsonl`, `<date>-go-sdk.jsonl`, `<date>-ts-sdk.jsonl`); each day file gets its own `corpus/INDEX.md` row.
- The record line (`docs/records/<yyyymmdd>-fuzz-campaign-divergences.jsonl`) is written by a batch that wrote a row
  (no longer by every batch with a divergent cell) and carries `parts`, `part_seeds`, `engines` (per engine its counts,
  rules, or the skip's reason), `replay`, `divergent_by_part` and `witness_files` (each with its sha256).

## How the captain restarts the loop

The loop must stop before its tree moves: it reads `tools/fuzz_compose.py`, which the old driver never called.

```sh
touch ~/bsv/targets/spec-fuzz/STOP                                    # ends the loop at the next batch boundary, nodes stopped
while [ -e ~/bsv/targets/spec-fuzz/loop.pid ]; do sleep 5; done       # the loop removes loop.pid on exit
rm ~/bsv/targets/spec-fuzz/STOP
cd ~/bsv/worktrees/spec-box-fuzz && git fetch origin && git merge --ff-only origin/main   # once this lane is on main
(cd harness && CARGO_BUILD_JOBS=4 cargo build --release --locked --bin seed_gen --bin run_svnode --bin run_engine)   # load under 20; seed_gen gained --family, run_engine is new to this tree
PATH="$HOME/bsv/targets/spec-box/toolchains/go/bin:$HOME/bsv/targets/spec-box/toolchains/node/bin:$PATH" make gosdk-build tssdk-install   # the SDK runners (harness/README.md); absent, each engine is SKIPPED BY NAME
nohup tools/fuzz_campaign.sh >/dev/null 2>&1 &
```

If the merge moves `lean/`, the tree's `lean/.lake/build` must be rebuilt outside the loop (one slot of the Lean lock)
or `eval/bsvs` refuses (exit 3) and the loop logs it. The counter continues; the started line names the engines' state.
