For the local work budget, the CHANGELOG says **“Migration: add `work_limit:
None` to spend parameter literals”**. This is a local evaluator budget inside
one input, charged by reached opcodes and bytes hashed. It is distinct from
the stream cursor's pause between inputs. The following review names the
harness's affected interfaces and the related interfaces it does not call.

| API at 0.4.5 | harness use and adaptation |
|---|---|
| `SpendParams`, `Spend::new` | `harness/src/engine.rs` has the sole parameter literal. Add `work_limit: None`, preserving the recorded unbounded-work configuration. `memory_limit` and all flag configuration remain as recorded. |
| `Spend::validate`, its internal `Spend::step` | The runner calls `validate`; the release adds work charging in `step`, hash operations and signature checks. With `None`, the runner does not opt into a work cap. It does not call `step`, `reset` or the new `work_spent` accessor directly. |
| `ScriptEvaluationError::resource_limit`, `ScriptResourceLimit`, `ScriptResource::Work` | The runner already handles every `Some(resource_limit)` before interpreting validity, recording `undecided`. It formats `resource`, `limit` and `attempted`; the latter two are now `u64`, which requires no formatting change. It constructs no resource literal, matches no individual variant and does not read the new `work_spent` field. |
| `Spend::set_flags`, `set_require_push_only`, `set_require_minimal` | These runner calls retain their signatures and behavior; the public-call review and release build require no adaptation. |
| `TxSighashCache` | Used internally by `Spend::new`; 0.4.5 adds hash-cost accounting. The harness does not construct this cache or call its internal `hashing_work`. |
| `build_sighash_preimage`, `compute_sighash_for_signing`, `SighashParams`, `TxInput`, `TxOutput` | These are the sighash generator's public APIs. The module adds cache accounting, but these definitions and signatures remain unchanged. The runner also constructs the two transaction-part types. |
| `TxSpendParams`, `Spend::with_transaction` | Not used; the new parameter field therefore adds no other literal here. |
| `StreamVerifier::set_work_limit`, `AsyncStreamVerifier::set_work_limit`, `SpendRefusal::Resource`, stream `step_until`/`resume` | Not used by the runner or four vector generators; no stream pause, cursor or step-budget migration is required. |
| `ScriptNum`, `BigNumber`, EC key/signature APIs, hash primitives, `ScriptFlags`/`ProtocolEra` | The number/arithmetic codecs and operations, ECDSA generator APIs and runner hash/flag code remain byte-identical in the reviewed modules. Their generators are rebuilt and re-run below. |
