## Node and document, where they differ [SRC] / [LIT]

Recorded in the module's docstring with both citations: the node hashes once where the document
writes HASH256/Hash256; the miner-info signature is checked for length only (the document is bound
by its txid inside the block bind); the node takes the lowest-index prefixed output of the
miner-info transaction, the document says index 0; the 0.3 document's height is never compared with
the block's; the DER-string pattern admits 64 to 72 bytes where the document says 70 to 72; a 0.3
static document in the old format is always refused; one error text mislabels its code. Two facts
of the database are stated as theorems or docstrings: the reputation test reads the miner's
reputation and not the id's state (`goodReputation_state_blind`, src/miner_id/miner_id_db.cpp:299-329),
and a revocation's unlinking of recent blocks edits the in-memory table only (miner_id_db.cpp:1153-1166).
The datareftx message's merkle proof writes 32 bytes for every node (src/merkleproof.h:26-45),
unlike the TSC binary form's value-less duplicate; it is not modelled as a codec here.
