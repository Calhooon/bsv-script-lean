## The second oracle

[SRC] Teranode v0.16.0 at `4edb60a40c6628ff0ef60231c2628efd7103fde5`: the question does not arise in this form. There is no pool
file and no persistence switch; a validated transaction is written to the UTXO store with `unmined_since` set when it carries no
mined block (`stores/utxo/sql/sql.go:468-471`, the backend of the instance of record), and block assembly's start reloads every
unmined transaction from the store's index (`services/blockassembly/BlockAssembler.go:1299-1323`, `loadUnminedTransactions` at
`:3199`, the iterator at `:3276`), checking parent chains by default (`settings/blockassembly_settings.go:50`) and removing the
invalid ones only when `blockassembly_onRestartRemoveInvalidParentChainTxs` is set (default false, `:52`);
`utxostore_unminedTxRetention` (144 blocks, `settings/utxostore_settings.go:12`) is the window after which pruning preserves an
unmined transaction's parents for its resubmission; it removes nothing at a restart. Survival across a restart is the
store's durability there; what the reference drops on load by expiry has no counterpart at restart.
