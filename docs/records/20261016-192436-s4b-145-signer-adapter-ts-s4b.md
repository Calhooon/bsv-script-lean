## What each method hands the SDK

| method | SDK call and observation |
|---|---|
| `template` | `P2PKH.unlock(...).sign` receives the key, supported scope, real prevout amount and real locking script; no source transaction is fabricated. Its complete returned unlock is kept. Unsupported templates/scopes are null with reasons. The template does not expose its preimage; it is recomputed using the same SDK formatter and parameters. |
| `api-default` | `TransactionSignature.format` receives the real locking script as `subscript`, exactly the script a template resolves by default. Each signature is `PrivateKey.sign(Hash.sha256(preimage))`, wrapped by the SDK's `TransactionSignature.toChecksigFormat`. |
| `api-scriptcode` | the same API receives the row's `scriptcode_hex` verbatim as `subscript`. The SDK's own algorithm selection and script serialization are retained, even when they change the supplied bytes. |

[D] Every digest is recomputed with SDK `Hash.hash256` over the SDK-returned
preimage. No signature function returns a digest field. There is no custom nonce,
backend, legacy SINGLE correction or verifier-era override. The row's version,
locktime and each input sequence are applied before signing; outputs, outpoints,
literal unlock bytes and signature order are preserved.

[D] Input is the shared Entry plus `signing`; output has exactly the shared
`id`, `engine`, `method`, `tx_hex`, `inputs`, `note` fields. Both positional paths
and `--corpus <file> --out <file>` work. Every row produces [D] 3 method lines,
including unavailable methods. Method failures are isolated and carry their reason;
unparseable JSON is a file error. The input must have empty unlocking scripts and
matching prevouts, with each input covered once by the signing metadata.

[D] `<sigK>` and `<pubK>` stand for complete data pushes, including the push opcode.
`<preimageN>` pushes the SDK preimage at CHECKSIG site N. `scriptcode_hex` is a list,
one entry per site in execution order; `sig_sites[K]` maps private/public key K to a site.
The counts of keys and sites can differ. Every input requires `pubkeys` and `unlock_template`
for every method; unknown template names produce `unknown template` on every method.
The names are `p2pkh`, `p2pk`, `multisig-<m>-of-<n>`, `checksig-in-unlock-a`,
`checksig-in-unlock-b`. Each trace names its input `index` and CHECKSIG `site`, keeping
preimage/digest/script fields scalar. `scriptcode_used_hex` is the script handed to the
SDK, and `scriptcode_serialized_hex` separately records the SDK's serialized script.
