## 2. What moved (the CHANGELOG at `v0.7.0`, by heading) [LIT]

- **0.7.0, "The default signing digest is the node's"**: `SigningContext::compute_sighash` (every template's
  `unlock` and `Transaction::sign`) now dispatches by hash type through `compute_sighash_dispatched_for_signing`
  (BIP143 only for FORKID without CHRONICLE, the original digest otherwise, the constant one for original SINGLE beyond
  the outputs); a scriptCode override `SigningContext::with_script_code` and the helper
  `script::chronicle_unlocking_script_code`; an absent input index is an `Err`.
- **0.7.0, "The identity token signatures (the review of 0.7.0)"**: the identity module's three signing paths sign the
  dispatched digest (the lens finding on #148).
- **0.7.0, "Notes: cross-SDK parity"** and **"The lint bar"**: notes and lints.
- **0.6.1, "Incremental hashing"**: `Sha256` / `Sha256d` hashers; one-shot hashes unchanged.
- **0.6.0, "Chain primitives"**: `BlockHeader`, `CompactTarget`, `U256`, merkle roots with the mutated flag; and
  `Reader::read_var_int` now refuses non-canonical encodings in transactions, BEEF and BUMP (the node's
  `ReadCompactSize`), `read_var_int_lenient` keeping 0.5's reading.

## 3. Consensus or policy default

- Consensus: **no**. Nothing in the three releases changes a node rule; bsv-rs is an implementation under measurement.
  The signing changes align the library's default signer with the node's existing `SignatureHash` dispatch (bitcoin-sv
  v1.2.3 `6504a3af` `src/script/interpreter.cpp:2112-2124`, `:2086-2100`, scriptCode `:1471-1481`) [SRC]; the
  canonical varint aligns its readers with the node's `ReadCompactSize`.
- Policy default: **no**. No policy limit or default moved in the library's script or transaction paths.
