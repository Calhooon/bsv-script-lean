## Adapter and interface

[D] Read the existing Go verifier's `main.go`, `harness/src/engines.rs`,
`harness/src/bin/run_engine.rs` and the engines section of `harness/README.md`.
`run_engine` spawns `gosdk-runner` (or `GOSDK_RUNNER`) and exchanges a verifier
request envelope. This adapter is a separate executable reading the shared
signer Entry directly, leaving the verifier protocol intact.

[X] `harness/engines/go/signer` supplies `--corpus`, `--out`, stdin/stdout and
`--version`. Build with `make gosdk-signer-build`; the default destination is
`harness/target/engines/gosdk-signer`. In this lane, `GOSDK_SIGNER_BIN` redirects
the executable to `$CARGO_TARGET_DIR/engines/gosdk-signer`, and `GOCACHE` is
`$CARGO_TARGET_DIR/go-cache`. Scratch uses `$TMPDIR`. No build output is kept
in the checkout.

| method | SDK input and recorded output [D] |
|---|---|
| `template` | P2PKH `Unlock(key, &flag).Sign(tx, index)` receives the real coin. The complete SDK unlocking script is used. Other shapes return null with the unavailable template named. |
| `api-default` | The ordinary SDK digest and matching exported preimage reader receive the real coin's locking script; `PrivateKey.Sign` signs that digest. |
| `api-scriptcode` | The same functions receive the row's scriptCode through `SetSourceTxOutput`; its value is preserved, and no `SourceTransaction` is attached. |

The adapter measures `Sign`; the dispatcher's `SignWithCache` is documented identical at p2pkh.go:65-68 and is not measured separately.

[D] Every method gets a fresh decode. The row's version, locktime and input
sequences are applied exactly. Every input must have an empty unlocking script
and a matching prevout. Input failures produce a null transaction with a reason;
the stream proceeds to the other methods and rows. SDK panics are recorded as
nulls, never converted to a signature. The flag word and era are column metadata:
they do not override the public signing API's behavior.

[D] `scriptcode_hex` is a list of sites in execution order. `sig_sites[K]` maps
key K to its site, including multiple keys at one multisig site or an in-script
site without a host key. Each result names both the input index and the site. `scriptcode_used_hex` records the actual source
script handed to the SDK, before its own legacy code-separator processing.
For templates, the public preimage/hash calls are re-invoked with the same SDK
inputs as `Sign`; no independent preimage serializer is used in the adapter.

[D] Signature and key tokens expand to complete SDK data pushes. Literal hex
is preserved. An additive `<preimageN>` token inside the existing
`unlock_template` string pushes the SDK-returned preimage at site N; no JSON
field was added. This is needed for the recorded OP_PUSH_TX shape, which puts a
preimage on the stack rather than a host-created signature at that site. The captain adopted this token in #145 ruling S1; the fix round follows the corpus contract. The common signature and
public-key tokens retain their specified meaning.
