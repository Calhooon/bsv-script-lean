## The design

| part | what |
|---|---|
| the batch | batch n: `seed_gen --seed S --count 50000` with S = `0x` + the leading 16 hex digits of sha256(`spec-fuzz-campaign batch n`) (batch 1: `0xca1872e03c5cb8c8`); `eval/bsvs corpus` (the spec's two columns, stamp `spec@<commit>`); `run_svnode --dump` with `--rpc`/`--cookie` and `--rpc-mempool`/`--cookie-mempool` naming the campaign's instances, the witnesses to the batch's scratch directory; the counter file advances only on a completed batch, so a failed batch is retried under the same seed |
| the generator | the seed corpus's own (`harness/src/bin/seed_gen.rs`, the families of `harness/src/gen.rs`), the one the bench leg's fuzz smoke runs (`tools/bench_leg.sh`, #137); every case is decided by bsv-rs inside seed_gen as well (its verdict rides in the witness row's `spend.expect`) |
| the comparison | per spend and column, the spec's verdict against `verifyscript`'s, under the spec's own flag word (`harness/src/flags_oracle.rs`), the node's description mapped back by `harness/src/svnode_codes.rs`, each divergence filed by the classifier table `harness/rules/sv-node.json` (an unmatched one is `unexplained`) |
| the node | two fresh regtest instances of the pinned build (`~/bsv/targets/sv-v1.2.3/bin/bitcoind`, bitcoin-sv v1.2.3 at `6504a3af`) on the oracle's two confs (`harness/oracle/bitcoin.conf`, zeroed caps: the `spec` column; `harness/oracle/bitcoin-policy.conf`, the node's defaults: `spec-mempool`), datadirs `~/bsv/targets/spec-fuzz/node-{consensus,policy}`, RPC 18601 and 18603, P2P 18602 and 18604 (`listen=0`); a port outside 18601 to 18620 is refused, the standing instances (18563, 18565, 18567), the runner's band (18571 to 18590, `harness/src/scenarios/core.rs`, `tools/rpc_probe.py`; `tools/cpp_era_run.sh`'s 18583 to 18586 inside it) and the mini are never named; each instance is health-checked before every batch and restarted on a fresh datadir when it does not answer; stdout and stderr to `~/bsv/targets/spec-fuzz/log/node-<instance>.{out,err}` |
| the load | before every batch, a 1-minute load under 12 (`FUZZ_LOAD_MAX`), else a 60 s wait: the campaign yields to every lane (their bar is 20, CLAUDE.md rule 17) |
| what it writes | per batch one line of `~/bsv/targets/spec-fuzz/log/<date>.log` (outside the repository); per divergent cell one witness row of `corpus/fuzz/<date>.jsonl` (the harness's witness shape: a corpus Entry with `expect` and `divergence`, the campaign's fields under `fuzz`), per divergent batch run_svnode's own witnesses as `corpus/fuzz/<date>-batch-<n>-sv-node.jsonl` and one record line of `docs/records/<yyyymmdd>-fuzz-campaign-divergences.jsonl`, both in the campaign's worktree (the format: `corpus/fuzz/README.md`), `ruling: open`; nothing committed by the loop |
| what it never does | a Lean build, `make axioms`, StaleRunCheck, a cargo build (the binaries are the campaign worktree's own: `harness/target/release/{seed_gen,run_svnode}` built once by hand with `CARGO_BUILD_JOBS=4`, and `lean/.lake/build` cloned from a built box worktree at the same Lean sources; `eval/bsvs` refuses a stale binary with exit 3 and the loop then logs it and, after three failures, waits 1,800 s); a judgement of a divergence (rule 4) |

## How to start, stop and read it

```sh
cd ~/bsv/worktrees/spec-box-fuzz && git fetch origin && git merge --ff-only origin/main   # once this lane is on main
nohup tools/fuzz_campaign.sh >/dev/null 2>&1 &                         # the standing loop
touch ~/bsv/targets/spec-fuzz/STOP                                     # stop: at the next batch boundary (within 60 s during a failure wait), both nodes stopped
rm ~/bsv/targets/spec-fuzz/STOP                                        # before the next start
tools/fuzz_daily.sh [YYYY-MM-DD]                                       # the day's line (default today, UTC)
```

A second loop on the same state is refused (`loop.pid`). After the campaign worktree moves to a tree with other Lean
sources, its `lean/.lake/build` must be rebuilt outside the loop (one slot of the Lean lock) or `eval/bsvs` refuses.

**The daily line.** `<date> batches B (red R, failed F) spends S divergences D (unexplained U) undecided X no-spec Y
witnesses <file|none> record <file|none>`: B batches completed that day, R of them with run_svnode's verdict RED (an unexplained divergence,
a node description outside the table or a flag-word drift), F stopped before a verdict (retried under the same seed);
S spends compared; D divergent cells (two cells per spend), U of them matching no row of the classifier; X the node's
undecided runs (a timeout or a skip), Y the entries without a spec verdict (run_svnode's GREEN tests neither); the witness
file and the record file of the day in the campaign's worktree, indexed there by the same step (rule 12) for the
captain's lane to land. `divergences 0` with `undecided 0` and `no-spec 0` is the day's fidelity count on that day's fresh cases, scoped to the generator's
families, the pin and the two instances' confs; a non-zero day is a Finding for the captain, never judged by the loop.
